# 014_news_horizon_decay

연구 메모 1번 결론("월별 지평에서는 뉴스의 증분 예측력이 유의하지 않다 — 신호가 며칠 안에
가격에 흡수돼 빠르게 소멸하기 때문")을 일별 vs 월별 지평 비교로 직접 검증한다.

`raw/news`는 기업명 검색이 아니라 경제일간지 카테고리 전체라 그 날/그 달 전 종목에 동일한
값이 붙는다(008 README). 그래서 종목별 순위(Rank IC)가 아니라 **"뉴스 신호 → 다음 지평
시장 평균 수익률"의 시계열 예측**으로 검증한다 — 종목별 baseline 팩터 모델이 필요 없고,
008/009/011/012처럼 base_rank 상호작용 틀을 가져올 필요도 없다.

**비교는 "뉴스 단독"이 아니라 "수익률 baseline 대비 뉴스의 증분가치"다**(009의 틀을 시장
단위로 축소): 모델 A(baseline, 오늘 수익률 → 다음 기간 수익률) vs 모델 B(오늘 수익률 +
오늘 뉴스 피처 → 다음 기간 수익률)를 일별/월별 각각 비교한다. baseline이 `raw/daily_price`/
`raw/returns`의 단순 수익률이라 추가 수집 없이 지금 데이터로 끝난다 — **macro·투자자별
거래(trading flow) 일별 수집과 정교한 모멘텀(mom_12_2 같은 다구간 스펙)은 015번 실험으로
분리**했다(008/009 수준 23개 팩터를 일별로 복제하려면 일별 투자자 거래데이터·일별 외국인
보유비율을 새로 수집해야 해서 작업량이 큼).

## 단계

| 단계 | 상태 | 내용 |
|---|---|---|
| 1. 일별 뉴스 전처리 + 샘플링 | **구현됨** | PREPROCESSING.md 1~4·6번 필터(008과 동일) 적용 후, 날짜별로 필터 통과 기사의 10%를 무작위 샘플링. 일별 집계든 월별 집계든 같은 표본의 부분합이 되도록 날짜별로 독립 샘플링함 |
| 2. FinBERT 임베딩 | **구현됨** | 008과 동일 모델(`snunlp/KR-FinBert-SC`)·설정으로 기사 단위 768차원 [CLS] 임베딩. 008은 `month`로 캐시를 묶었지만 이건 `date`(일 단위)로 묶어서 저장 — 학습 없는 고정 변환이라 일별/월별 타깃과 무관하게 한 번만 하면 됨 |
| 3. attention pool (MLP 투영) | **구현됨** | MLP로 기사 중요도 학습 → 가중합 → N차원 투영(008/009 구조). daily_8/monthly_8 두 모델. 일별은 "직전 거래일 다음날~오늘 거래일" 윈도우로 주말·휴일 뉴스까지 묶어서 그룹핑. **daily_16(일별 16차원)도 시도했으나 daily_8보다 일관되게 나빠서(결과 참고) 코드에서 제거함 — 과거 결과만 `results/`에 남아있음** |
| 4a. 일별 수익률 패널 | **구현됨** | `raw/daily_price` → `raw/returns`와 동일 포맷(행=날짜, 열=종목코드 1,086개 동일 순서, 결측은 채우지 않음)으로 변환. train_2001_2021/test_2022_2025로 raw/returns와 동일하게 분리. 분할로 보이는 비정상 점프(±25% 초과)는 보정하지 않고 그 날 수익률만 결측 처리 |
| 4b. 시장 평균 수익률 | **구현됨** | 4a(일별)와 `raw/returns`(월별) 각각 등가중 평균 → 예측 대상이면서 동시에 모델 A/B의 baseline 입력으로도 재사용 |
| 5. 모델·비교 | **구현됨** | XGBoost 회귀로 모델 A(수익률만) vs 모델 B(수익률+뉴스) vs B_placebo(수익률+랜덤노이즈, 20시드 평균) 비교 |
| 6. 결과 플롯 | **구현됨** | `images/model_comparison.png` |
| 7. 시계열 롤링 검증 | **구현됨** | attention pool은 재사용, XGBoost만 6개 기간(2005/2009/2013/2017/2021/2025)으로 재학습해서 단일 분할 결과의 재현성 확인 |

## 1단계 설계에서 비자명한 부분

- **본문 길이 200자**: 008/009/011/012가 전부 쓰는 길이(`NEWS_BODY_CHARS=200`)를 그대로
  따름. BigKinds 비로그인 수집은 본문이 원래 이 정도만 채워져 있어서, 제목만 쓰면 텍스트가
  너무 짧아 임베딩/클러스터링이 잘 안 돼 "신호 없음"으로 잘못 보일 위험이 있음 — 그래서
  짧더라도 본문을 포함한다.
- **샘플링 방식이 008과 다름**: 008은 "일자별 기사 수 비중대로 월 1,000개"였는데, 이 실험은
  **그냥 날짜별로 10%씩 무작위 샘플링**한다. 일별/월별 두 지평을 같은 표본으로 비교하는 게
  목적이라, 날짜별로 독립 샘플링해야 월별 집계가 일별 표본의 단순 합으로 떨어진다(008 방식은
  월 단위로만 가중치를 맞춰서 날짜별 분해가 안 됨).
- **날짜(`date`)를 月이 아니라 일 단위로 보존**: 008의 `samples.csv.gz`는 `month` 컬럼만
  있어서 이 실험에 재사용할 수 없었음(다른 실험 폴더 import 금지 원칙과도 맞아서, 008 코드를
  복사해 날짜 단위로 고쳤음).
- **검증 방법**: `daily_counts.csv`를 월별로 합산한 `n_filtered`가 008의
  `news_cache/month_counts.csv`의 `n_articles`와 같아야 함(필터 로직이 동일하므로) — 1단계
  실행 후 대조 완료함(2026-11-20, 전부 일치).

## 2단계(FinBERT 임베딩)에서 비자명한 부분

- **이 서버는 GPU가 없음** (`nvidia-smi` 없음). 008 캐시 생성 시각으로 역산한 처리 속도가
  초당 약 23~25개 기사라, 10% 샘플 전체(약 293만 개)를 전부 임베딩하면 **약 1.4일** 걸림.
  연도 단위로 캐시하므로 중단 후 재실행하면 이미 끝난 연도는 건너뜀.
- **전체 뉴스(샘플링 없이)를 임베딩하는 건 이 서버에서 불가능**: 29,356,582개 전체를 하면
  약 90GB가 필요한데 디스크 여유공간이 33GB뿐임(2026-11-20 확인). 그래서 10% 샘플만 한다는
  원래 계획을 그대로 유지함.
- `month`가 아니라 `date`로 캐시를 묶음(008과 다른 점) — 이후 attention pool 단계에서
  일별로도 월별(날짜들을 묶어서)로도 그룹핑할 수 있어야 하기 때문.
- **메모리 누수(2026-11-20 발생)**: 서버에서 2001~2007년까지는 정상 처리됐으나(무결성 확인
  완료), 이후 RSS가 62.8GB까지 차서 프로세스가 강제 종료됨. 맥(MPS)에서는 같은 코드로 문제
  없었던 걸로 봐서 CPU(glibc malloc)가 연도를 반복할수록 해제된 메모리를 OS에 돌려주지 않고
  쌓아두는 단편화 문제로 추정. 연도 하나 끝날 때마다 `gc.collect()` + `malloc_trim(0)`으로
  강제 정리하고 현재 RSS를 로그에 남기도록 고침(`_release_memory`, `_current_rss_gb`).
- `SERVER_YEARS`(2001~2009)는 이 서버가 처리하는 연도만이고, 2010~2025년치
  `emb_<연도>.npz`는 다른 기기에서 만들어 같은 경로에 합쳐놓은 것임(별도 병합 코드 없이
  연도별 캐시 파일 존재 여부로 자동 인식됨).
- **cuda/mps/cpu 자동 감지**(`_device()`): 이 서버는 CPU뿐이지만, 다른 기기(GPU나 맥 MPS가
  있는)에 이 파일 하나만 그대로 복사해서 돌려도 알아서 가속기를 쓰도록 만들어둠 — 노트북용
  별도 파일을 다시 만들 필요 없음.

## 4단계(일별 수익률 패널)에서 비자명한 부분

- **`raw/returns`와 같은 파일 포맷을 그대로 따름**: 행=날짜(또는 월), 열=종목코드 1,086개를
  `raw/returns`와 동일한 순서로 유지하고, 제외/결측 종목도 열 자체는 남겨두고 값만 NaN으로
  둔다(raw/returns의 "결측은 채우지 않는다" 원칙 그대로). 기간 분리도 `train_2001_2021`/
  `test_2022_2025`로 raw/returns와 동일하게 맞췄다 — 나중에 015(일별 factor panel)에서
  이 파일을 그대로 재사용하거나 비교하기 쉽게 하기 위함.
- **분할 점프 처리**: 역산 보정(back-adjust)하지 않고, 하루 변동폭이 ±25%를 넘는 날의
  수익률 그 하루만 결측 처리한다. 다만 이 임계치가 KRX 가격제한폭(최근 ±30%, 2015년 이전
  ±15%)과 겹쳐서, 정상적인 상한가/하한가를 분할로 잘못 걸러낼 수 있다 — 1차 근사치이며
  검증 전.
- **제외 종목**: `PREPROCESSING.md` 7번(004730, 217590) + `raw/daily_price` README에 적힌
  거래일 5%+ 누락 4종목 + 고가/저가 역전 4종목, 총 10개.
- 출력은 `raw/`가 아니라 이 실험 폴더 `features/`에 저장(가공본이라 raw 폴더 원칙과 안 맞음).

## 결과 (2026-11-21)

**연구 메모 1번 결론("뉴스는 월별 지평에서는 안 먹히고, 신호가 빨리 소멸한다")과 방향이
일치하는 증거를 찾음 — 다만 일별 효과도 크지 않고, 월별 쪽은 애초에 판단이 불가능할
정도로 노이즈가 큼.**

단일 분할(test=2022~2025, placebo 20시드 평균) 결과 (`results/model_comparison.csv`):

| | A_baseline | B_news | B_placebo(평균±표준편차) |
|---|---|---|---|
| 일별-8차원 | 0.0645 | 0.0622 | 0.0517 ± 0.0325 |
| 일별-16차원 | 0.0645 | 0.0503 | 0.0483 ± 0.0237 |
| 월별-8차원 | -0.0441 | -0.0786 | -0.0657 ± 0.1325 |

시계열 롤링 검증(6개 기간, `results/walk_forward_cv_summary.csv`) — attention pool은
재사용하고 XGBoost만 재학습:

| | A_baseline | B_news | B_placebo |
|---|---|---|---|
| 일별-8차원 | 0.079±0.094 | **0.109±0.083** | 0.058±0.070 |
| 일별-16차원 | 0.079±0.094 | 0.062±0.073 | 0.045±0.075 |
| 월별-8차원 | -0.295±0.437 | -0.075±0.221 | -0.086±0.117 |

**해석**:
- **일별**: B_news가 baseline과 placebo를 6개 기간에 걸쳐 꾸준히 이김(단일 분할에서는
  baseline에 졌지만, 롤링 검증에서는 baseline도 이김). 차이가 placebo 표준편차보다
  작아서 강한 신호는 아니지만, 여러 기간에서 순서가 일관되게 유지된다는 점에서 단일
  분할보다 신뢰할 만함. **8차원이 16차원보다 일관되게 나음** — 월별뿐 아니라 일별도
  16차원은 과한 것으로 보임.
- **월별**: baseline 자체가 폭주함(표준편차 0.437 > 평균 절댓값 0.295) — 기간마다 결과가
  완전히 달라져서 애초에 결론을 낼 수 없음. 표본이 너무 작은(폴드당 12개월) 게 원인.
  단일 분할에서 placebo가 +0.106로 1등이었던 것도 20시드로 평균 내보니 -0.066으로
  뒤집혀서, 단순히 운 좋은 노이즈 한 번이었던 것으로 확인됨.
- **결론**: 가설(지평이 길어질수록 뉴스 신호가 소멸한다)과 방향은 맞지만, 일별 효과
  크기가 작고(Spearman 0.05~0.11대) 월별은 통계적으로 판단 자체가 불가능해서, "뉴스가
  일별에서는 확실히 유의하다"가 아니라 "일별이 월별보다 그나마 덜 나쁘다" 정도로 보수적
  으로 해석해야 함.
